Websites before AI vs. websites after AI — what actually changed.Websites vor und nach AI — die fundamentale Verschiebung im Überblick.

Key context & takeawaysKontext & Kernaussagen

For two decades, web architecture optimised for one consumer: the human reader, brought to the page by a search engine that scored links. Every visual flourish, every hero animation, every cookie banner existed to convert that human visitor. The whole craft assumed the visitor would arrive.

Zwei Jahrzehnte lang optimierte die Web-Architektur auf einen einzigen Konsumenten: den menschlichen Leser, geliefert durch eine linkbasierte Suchmaschine. Jede visuelle Geste, jede Hero-Animation, jedes Cookie-Banner existierte mit dem Ziel, diesen menschlichen Besucher zu konvertieren. Das gesamte Handwerk setzte voraus, dass dieser Besucher tatsächlich ankommt.

That assumption no longer holds. In 2026, the dominant consumer of a website is not a human browser — it is an autonomous retrieval agent operating on behalf of a Large Language Model. This agent does not see your hero image. It does not scroll. It does not get charmed by typography. It strips the DOM down to text, embeds that text into a vector space, and competes your content against thousands of other candidates on a single metric: semantic relevance to a user query [4].

Diese Annahme ist nicht länger tragfähig. Im Jahr 2026 ist der dominante Konsument einer Website kein menschlicher Browser, sondern ein autonomer Retrieval-Agent im Auftrag eines Large Language Models. Dieser Agent nimmt weder das Hero-Bild wahr, noch scrollt er oder reagiert auf typografische Gestaltung. Er reduziert das DOM auf Text, bettet diesen in einen Vektorraum ein und lässt die Inhalte gegen Tausende anderer Kandidaten antreten — auf einer einzigen, entscheidenden Metrik: semantische Relevanz zur Nutzeranfrage [4].

Client-side rendering and JavaScript-heavy single-page architectures present severe technical boundaries to modern RAG models, which often fail to complete full hydration scripts during automated extraction loops. Shifting to robust Server-Side Rendering (SSR) or edge-rendered static generation ensures that the complete raw HTML string is instantly available for machine ingestion [9, 11].

Client-side Rendering und JavaScript-lastige Single-Page-Architekturen stellen erhebliche technische Hürden für moderne RAG-Modelle dar, da diese während automatisierter Extraktionsschleifen die Hydration-Skripte häufig nicht vollständig ausführen. Der Übergang zu serverseitigem Rendering (SSR) oder edge-gerendertem statischen HTML stellt sicher, dass der vollständige Roh-HTML-String verzögerungsfrei für die maschinelle Ingestion bereitsteht [9, 11].

From PageRank rendering loops to RAG context windowsVom PageRank-Rendering-Loop zum RAG-Kontextfenster

The old rendering loop was conceptually simple. Googlebot fetched the HTML, followed the links, and built a graph in which authority flowed from page to page via the link structure. Site architecture was tuned to that loop — internal linking, sitemap.xml, canonical tags, rel="next" pagination. Every signal pushed toward a single goal: get the page indexed in the right place in the link graph.

Der klassische Rendering-Loop war konzeptionell überschaubar. Googlebot rief das HTML ab, folgte den Links und baute einen Graphen auf, in welchem Autorität über die Linkstruktur von Seite zu Seite floss. Die Site-Architektur war präzise auf diesen Loop abgestimmt — interne Verlinkung, sitemap.xml, Canonical-Tags, rel="next"-Pagination. Sämtliche Signale zielten auf ein einziges Ziel: die Seite an der korrekten Position des Linkgraphen zu indexieren.

The new loop is engineered around RAG (Retrieval-Augmented Generation) and vector alignment. An LLM scraper retrieves your page, strips it to raw text, splits it into chunks, embeds each chunk as a multi-dimensional vector, and stores those vectors in a database optimised for cosine-similarity search. When a user prompts the model, the system retrieves the closest-matching chunks and synthesises an answer from them [4, 6]. There is no link graph. There is no PageRank. There is only the question of whether your chunks land near the query in vector space.

Der neue Loop ist um RAG (Retrieval-Augmented Generation) und Vektor-Alignment herum konstruiert. Ein LLM-Scraper ruft die Seite ab, reduziert sie auf reinen Text, segmentiert diesen in Chunks, bettet jeden Chunk als hochdimensionalen Vektor ein und legt diese Vektoren in einer auf Cosine-Similarity optimierten Datenbank ab. Stellt ein Nutzer eine Anfrage, ruft das System die semantisch nächstliegenden Chunks ab und synthetisiert daraus die Antwort [4, 6]. Ein Linkgraph existiert nicht. PageRank existiert nicht.

The arrival of agentic search—including autonomous agentic e-commerce and agentic lead generation workflows where artificial agents research, qualify, and negotiate directly with other machine interfaces—means the fundamental nature of web interaction has evolved from a human-to-content model to an absolute agent-to-agent interface [9, 10].

Der Einzug der agentischen Suche — einschliesslich autonomer Workflows für agentischen E-Commerce und agentische Lead-Generierung, bei denen künstliche Agenten direkt mit anderen Maschinenschnittstellen interagieren, Angebote prüfen und Kaufentscheidungen treffen — transformiert das Web grundlegend von einer Human-to-Content-Interaktion zu einer reinen Agent-to-Agent-Schnittstelle [9, 10].

Decisively, the focus has shifted toward whether products and core services are prepared not just for humans, but for agents to understand, parse, and evaluate seamlessly [9, 12].

Der entscheidende Faktor verschiebt sich dahin, ob Produkte und Kernservices so aufbereitet sind, dass sie nicht nur von Menschen, sondern auch von Agenten reibungslos verstanden, geparst und evaluiert werden können [9, 12].

The token-density barrier — why marketing fluff actively harms you nowDie Token-Dichte als Barriere — warum Marketing-Fluff heute aktiv schadet

LLMs operate inside finite context windows. Every token consumed by a navigation wrapper, a cookie banner, a tracking script, or a flowery brand introduction is a token that cannot be spent on the substantive content the model needs to answer the question. In a competitive retrieval landscape, low token-density pages lose to high token-density pages every time.

LLMs operieren innerhalb endlicher Kontextfenster. Jeder Token, der von einem Navigations-Wrapper, einem Cookie-Banner, einem Tracking-Skript oder einer ausschmückenden Markeneinleitung beansprucht wird, fehlt der substanziellen Inhaltsebene, auf die das Modell zur Beantwortung der Frage angewiesen ist. In einer kompetitiven Retrieval-Landschaft unterliegt eine Seite mit niedriger Token-Dichte ausnahmslos einer Seite mit hoher Token-Dichte.

Modern AI scrapers compensate for this by aggressively stripping DOM noise — CSS, JavaScript, header/footer wrappers — to parse pure text strings [2, 6]. But stripping is lossy. Pages designed with separate semantic layers, clean heading hierarchies, and structured content blocks survive the strip cleanly. Pages designed as visual collages do not.

Moderne AI-Scraper kompensieren diese Realität durch aggressive Bereinigung des DOM-Rauschens — CSS, JavaScript, Header- und Footer-Wrapper — und parsen ausschliesslich reine Text-Strings [2, 6]. Dieser Strip-Prozess ist jedoch verlustbehaftet. Seiten mit klar getrennten semantischen Ebenen, sauberen Heading-Hierarchien und strukturierten Inhaltsblöcken überstehen die Bereinigung verlustfrei. Visuell-collagierte Seiten scheitern an diesem Schritt.

The five-step retrieval pipelineDie fünfstufige Retrieval-Pipeline

How an AI agent reads your websiteWie ein AI-Agent eine Website liest

  1. Scraping. The agent issues an HTTP request, identifies itself via its user-agent string, and pulls the raw response. If your robots.txt blocks the agent — or if your firewall returns a 403 — the pipeline ends here. Most accidental invisibility issues live in this single step.
  2. Structural stripping. The agent walks the DOM, removes scripts, styles, navigation, headers, footers, cookie banners and ad slots, and reduces the page to its semantic skeleton: headings, paragraphs, lists, tables, schema blocks [2, 6]. Pages that hide content behind JavaScript or place critical text inside non-semantic divs lose information here.
  3. Tokenization. The clean text is segmented into tokens — sub-word units the model can compute on. A 1 000-word page typically becomes 1 300–1 500 tokens. Token budget is finite. Every token spent on filler is a token unavailable for the substance the model needs.
  4. Vectorization. Each chunk is converted into a high-dimensional embedding vector. Cosine similarity between this vector and the user's query vector determines whether the chunk is retrieved [6]. Chunks that mix topics produce muddy vectors; tight single-topic chunks produce sharp ones.
  5. Answer synthesis. The retrieved chunks are passed to the generation step. The model assembles an answer, optionally cites the source URLs, and returns the response to the user. The chunks that survived the four prior steps are now your brand's only representation in the answer.
  1. Die Restriktion im Klartext. Der Agent initiiert einen HTTP-Request, identifiziert sich über seinen User-Agent-String und ruft die Roh-Response ab. Blockiert die robots.txt den Agenten — oder antwortet die Firewall mit einem 403-Status — endet die Pipeline an dieser Stelle. Die Mehrheit unbeabsichtigter Unsichtbarkeits-Probleme entsteht in genau diesem ersten Schritt.
  2. Die strategische Bedeutung. Der Agent durchläuft das DOM, entfernt Skripte, Styles, Navigation, Header, Footer, Cookie-Banner und Ad-Slots und reduziert die Seite auf ihr semantisches Skelett: Headings, Absätze, Listen, Tabellen, Schema-Blöcke [2, 6]. Seiten, die kritische Inhalte hinter JavaScript verbergen oder substanziellen Text in nicht-semantische Divs platzieren, verlieren in diesem Schritt unwiederbringlich Information.
  3. Auswirkungen auf den operativen Workflow. Der bereinigte Text wird in Tokens segmentiert — Sub-Word-Einheiten, auf denen das Modell rechnen kann. Eine 1 000-Wort-Seite resultiert typischerweise in 1 300–1 500 Tokens. Das Token-Budget ist endlich. Jeder Token, der in Füllmaterial fliesst, fehlt der substanziellen Aussage, auf die das Modell zugreifen müsste.
  4. Die kommerziellen Kosten für das Unternehmen. Jeder Chunk wird in einen hochdimensionalen Embedding-Vektor überführt. Die Cosine-Similarity zwischen diesem Vektor und dem Query-Vektor des Nutzers entscheidet, ob der Chunk retrieved wird [6]. Themenvermischte Chunks produzieren unscharfe Vektoren; eng fokussierte Ein-Thema-Chunks erzeugen präzise Vektoren.
  5. Der strategische Workaround. Die retrieved Chunks werden an die Generierungsstufe übergeben. Das Modell konstruiert daraus die Antwort, zitiert optional die Quell-URLs und liefert die Response an den Nutzer aus. Die Chunks, welche die vier vorangegangenen Schritte überstanden haben, repräsentieren in diesem Moment die einzige Manifestation Ihrer Marke innerhalb der generierten Antwort.

AI agents do not browse websites in the visual sense; they consume structured programmatic data streams [9]. Consequently, an API-first content infrastructure backed by headless asset distribution and high-fidelity textual metadata (including highly descriptive, information-rich image alt texts) represents a key differentiator over legacy visual templates [9]. Furthermore, web architects must subject money pages to the 30-second extractability test: if an automated crawler cannot instantly lift who the page is for, what specific claim it validates, and why the brand is uniquely qualified within the first 512 characters, the RAG alignment fails and the brand is excluded before human judgment ever occurs [10].

AI-Agenten surfen nicht im visuellen Sinne; sie konsumieren strukturierte Datenströme [9]. Eine API-first Content-Infrastruktur, gestützt auf Headless-Asset-Distribution und datenreiche textuelle Metadaten (einschliesslich hochpräziser, informativer Bild-Alt-Texte), bildet daher einen entscheidenden Wettbewerbsvorteil gegenüber starren visuellen Layouts [9]. Zudem muss jede geschäftsrelevante Seite dem 30-Sekunden-Extraktionstest standhalten: Kann ein automatisierter Crawler nicht binnen der ersten 512 Zeichen fehlerfrei extrahieren, für wen die Seite bestimmt ist, welche konkrete Behauptung sie validiert und warum die Marke qualifiziert ist, bricht das RAG-Alignment ab und die Marke wird ausgeschlossen, noch bevor ein Mensch in den Auswahlprozess involviert ist [10].

The RAG sweet spot — why 256–512 characters wins for technical contentDer RAG-Sweet-Spot — weshalb 256–512 Zeichen bei technischen Inhalten überlegen sind

Recent benchmarks from a systematic chunking-strategy analysis demonstrate that, for technical and factoid Q&A, keeping chunk sizes tightly bounded to 256–512 characters keeps the vector representation pure and maximises precision [2, 6]. Larger chunks bring more context but introduce semantic noise — the chunk's vector now averages two or three competing topics, blunting its cosine-similarity score against a focused query.

Aktuelle Benchmarks aus einer systematischen Chunking-Strategie-Analyse belegen: Für technisches und faktenbasiertes Q&A bewahrt die enge Begrenzung der Chunk-Grösse auf 256–512 Zeichen die Vektor-Repräsentation in maximaler Präzision [2, 6]. Grössere Chunks transportieren zwar mehr Kontext, führen jedoch semantisches Rauschen ein — der Vektor mittelt nunmehr zwei oder drei konkurrierende Themen und verliert dadurch an Schärfe gegenüber einer fokussierten Anfrage.

Practically, this means three architectural rules. One: every H3-anchored block should contain one and only one factual claim or definition. Two: paragraphs should be 2–3 sentences maximum — long enough to carry a complete thought, short enough to remain a single retrieval unit. Three: structured elements (tables, definition lists, FAQ blocks) should be preferred over prose whenever a fact can be expressed structurally.

In der Praxis ergeben sich daraus drei architektonische Regeln. Erstens: Jeder H3-verankerte Block transportiert exakt eine Faktenaussage oder Definition. Zweitens: Absätze umfassen maximal zwei bis drei Sätze — ausreichend für einen vollständigen Gedanken, kompakt genug, um als einzelne Retrieval-Einheit zu bestehen. Drittens: Strukturierte Elemente — Tabellen, Definitionslisten, FAQ-Blöcke — sind der Prosa stets vorzuziehen, sobald sich ein Sachverhalt strukturell ausdrücken lässt.

Why direct openers work — the first 60 words decideWeshalb Direct-Opener wirken — die ersten 60 Wörter entscheiden

Princeton's GEO research found that adding direct-answer openers in the first 60 words lifts citations by 27 % [1, 5]. The mechanism is mechanical, not stylistic: when a model has to summarise or quote a source, it preferentially grabs text that already looks like an answer — a complete sentence stating the fact, near the top, in low-ambiguity language. Pages that bury the answer below three paragraphs of brand throat-clearing simply get skipped over for cleaner candidates.

Die GEO-Forschung der Princeton University belegt: Direct-Answer-Opener innerhalb der ersten 60 Wörter heben die Citation-Rate um 27 % [1, 5]. Der zugrundeliegende Mechanismus ist technisch, nicht stilistisch: Soll ein Modell eine Quelle zusammenfassen oder zitieren, greift es bevorzugt auf Text zu, der bereits als Antwort exakt formuliert ist — ein vollständiger Satz, der den Sachverhalt direkt benennt, prominent positioniert, in unmissverständlicher Sprache. Seiten, welche die eigentliche Aussage unter mehreren Absätzen Marken-Präambel verbergen, werden zugunsten klarerer Kandidaten konsequent übersprungen.

Combine the 60-word rule with the 256–512-character chunk rule and a structural pattern emerges: every page should open with a tight 2–3 sentence answer block under the H1, followed by structured sections that expand each claim under a dedicated, anchored H2 or H3. This is the architectural fingerprint of an AI-ready page.

Die Kombination der 60-Wörter-Regel mit der 256–512-Zeichen-Regel ergibt ein klares strukturelles Muster: Jede Seite eröffnet mit einem präzisen Antwort-Block aus zwei bis drei Sätzen unmittelbar unter dem H1, gefolgt von strukturierten Sektionen, die jede Aussage unter einem eigenen, verankerten H2 oder H3 vertiefen. Dies ist der architektonische Fingerabdruck einer AI-ready Seite.

Baseline 1 · Crawl optimisationBaseline 1 · Crawl-Optimierung

Crawl optimisation begins with robots.txt. Crawl-Optimierung beginnt mit der robots.txt. The second crawl-optimisation lever is llms.txt. The standard has officially been formalised as the machine sitemap. Located at the root (/llms.txt), it uses clean Markdown, an H1 site title, a blockquote site abstract, and explicit documentation arrays pointing to key pages and their Markdown variants [3, 4]. Baseline 2 · Linked entity graphBaseline 2 · Linked Entity Graph

Entity ambiguity is the silent killer of brand citation. If your company name is shared with another organisation — a common condition in B2B — the model has no way to know which one your page describes unless you wire the identity explicitly. The fix is Schema.org JSON-LD, but a level past the basic boilerplate.

Entity-Mehrdeutigkeit erweist sich als stiller Killer der Brand-Citation. Wird ein Firmenname mit einer anderen Organisation geteilt — im B2B-Umfeld ein häufig anzutreffender Sachverhalt — verfügt das Modell über keinerlei Möglichkeit zu erkennen, welche Entität die Seite tatsächlich beschreibt, solange die Identität nicht explizit verdrahtet ist. Die Lösung liegt in Schema.org-JSON-LD, allerdings eine Stufe oberhalb des Standard-Boilerplates.

Modern GEO practice connects organization nodes directly to Wikidata Q-IDs and Google Knowledge Graph MIDs via the sameAs property [5]. This single addition turns an isolated brand mention into a verifiable node in the global linked-data graph — the AI now has a canonical reference for who you are, and ambiguity collapses.

Die moderne GEO-Praxis verknüpft Organization-Knoten via sameAs-Property unmittelbar mit Wikidata-Q-IDs und Google-Knowledge-Graph-MIDs [5]. Diese einzelne Ergänzung transformiert eine isolierte Markenerwähnung in einen verifizierbaren Knoten innerhalb des globalen Linked-Data-Graphen — die AI verfügt nunmehr über eine kanonische Referenz zur Identität, und die Mehrdeutigkeit löst sich auf.

To anchor entity trust firmly across large language models, structured markup must be reinforced by absolute NAP (Name, Address, Phone) consistency across all external knowledge bases and directory profiles. Discrepancies in core business data degrade a model's evaluation vectors, causing retrieval filters to flag the entity as unverified or high-risk [11].

Engineer-grade FAQ.FAQ auf Engineering-Niveau.

Direct answers to the questions that come up when an architecture team starts building against this playbook.

Direkte Antworten auf jene Fragen, die sich stellen, sobald ein Architektur-Team beginnt, gegen diesen Praxisleitfaden zu implementieren.

Does a headless CMS data layer change the chunking strategy?Verändert ein Headless-CMS-Daten-Layer die Chunking-Strategie?

Yes, in two ways. First, the headless model encourages discrete content blocks at the data layer — which is good — but those blocks need explicit length contracts (256–512 characters) enforced at the schema level, not at the front-end. Second, the API response itself becomes a parallel surface AI agents can retrieve; make sure your API returns Markdown-rendered field values and not just raw RTF or JSON tokens, otherwise the chunk arrives at the model as noise.

Ja, in zweifacher Hinsicht. Erstens begünstigt das Headless-Modell diskrete Inhaltsblöcke bereits auf der Daten-Ebene — was grundsätzlich vorteilhaft ist —, jedoch benötigen diese Blöcke explizite Längen-Verträge (256–512 Zeichen), die auf Schema-Ebene durchgesetzt werden, nicht im Frontend. Zweitens fungiert die API-Response selbst als parallele Oberfläche, auf die AI-Agenten zugreifen können. Die API muss daher Markdown-gerenderte Feldwerte zurückgeben und nicht bloss rohes RTF oder JSON-Tokens — andernfalls erreicht der Chunk das Modell als Rauschen.

How do we handle vector collisions between near-duplicate product pages?Wie behandelt man Vektor-Kollisionen zwischen nahezu duplikaten Produktseiten?

Vector collisions occur when two pages embed to nearly identical points in vector space — the model retrieves only one, and the other becomes effectively invisible. The fix is differential entity wiring: each page must carry a unique @id, distinct sameAs references where possible, and at least one unique structured fact in the first 60 words. Avoid copy-pasted opener paragraphs across product variants — they are the single biggest cause of collision.

Vektor-Kollisionen entstehen, sobald zwei Seiten an nahezu identische Punkte im Vektorraum eingebettet werden — das Modell ruft lediglich eine ab, die andere wird faktisch unsichtbar. Die Lösung besteht in differentieller Entity-Verdrahtung: Jede Seite trägt eine eindeutige @id, möglichst distinkte sameAs-Referenzen sowie mindestens ein einzigartiges strukturiertes Faktum innerhalb der ersten 60 Wörter. Kopierte Opener-Absätze über Produktvarianten hinweg sind konsequent zu vermeiden — sie stellen die häufigste Kollisionsursache dar.

What server load do recursive AI scrapers actually generate?Welche Server-Last verursachen rekursive AI-Scraper tatsächlich?

Significant and growing. Public Cloudflare and Fastly reports place AI agent traffic at 15 %+ of total bot traffic on B2B properties, with crawl volumes from agentic systems doubling roughly every nine months. Practical implications: serve aggressive gzip/brotli compression to recognised AI user-agents, cap concurrent crawl rate at the edge, and consider pre-rendered HTML snapshots in object storage that agents can pull at near-zero compute cost.

Erheblich und mit anhaltend steigender Tendenz. Öffentliche Cloudflare- und Fastly-Reports verorten den AI-Agent-Traffic bei mehr als 15 % des gesamten Bot-Traffics auf B2B-Properties, wobei sich die Crawl-Volumina agentischer Systeme etwa alle neun Monate verdoppeln. Praktische Konsequenz: aggressive gzip- und brotli-Kompression an identifizierte AI-User-Agents ausliefern, gleichzeitige Crawl-Rate am Edge begrenzen und prerendered HTML-Snapshots im Object Storage bereithalten, die Agenten bei nahezu null Compute-Kosten abrufen können.

Does llms.txt replace sitemap.xml?Ersetzt llms.txt die sitemap.xml?

No. The two coexist and serve different consumers. sitemap.xml remains the standard for classic search engine crawlers — Googlebot, Bingbot — and supports indexable-URL discovery. llms.txt is the structured Markdown index for LLM retrieval agents, optimised for context-window-efficient ingestion. Maintain both; do not let a CMS migration drop either.

Nein. Beide Formate koexistieren und adressieren unterschiedliche Konsumenten. Die sitemap.xml bleibt der Standard für klassische Suchmaschinen-Crawler — Googlebot, Bingbot — und unterstützt die Discovery indexierbarer URLs. Die llms.txt ist der strukturierte Markdown-Index für LLM-Retrieval-Agenten, optimiert auf kontextfenster-effiziente Ingestion. Beide sind dauerhaft zu pflegen; eine CMS-Migration darf keines der beiden Artefakte verlieren.

What about JavaScript-rendered content — do AI agents execute JS?Wie verhält es sich mit JavaScript-gerendertem Inhalt — führen AI-Agenten JS aus?

Heterogeneously. Some agents (PerplexityBot, OAI-SearchBot variants) execute a limited JavaScript subset; others (early ClaudeBot, CCBot) do not. The defensive architectural rule is to ensure all critical retrieval content is present in the initial HTML response and progressively enhanced afterwards — never to depend on JS for the existence of substantive text. Server-side rendering or edge-rendered SSG are the safe choices.

Heterogen. Bestimmte Agenten (PerplexityBot, OAI-SearchBot-Varianten) führen ein begrenztes JavaScript-Subset aus; andere (frühe ClaudeBot, CCBot) tun dies nicht. Die defensive architektonische Regel lautet: Sämtliche kritischen Retrieval-Inhalte müssen in der initialen HTML-Response vorliegen und können erst im Nachgang sukzessiv erweitert werden — die Existenz substanziellen Texts darf nie von JavaScript abhängen. Server-Side Rendering oder edge-gerendertes SSG sind die verlässlichen Optionen.

How should multilingual estates structure their AI-readiness?Wie strukturieren mehrsprachige Estates ihre AI-Readiness?

Maintain a separate /llms.txt per language-prefixed root (or hreflang-aware sections), wire inLanguage properties through the JSON-LD, and ensure every translated page mirrors the heading anchor structure of its source. Models trained primarily on English content frequently misroute non-English queries — explicit language signals at the entity and chunk level minimise that loss.

Eine separate /llms.txt pro sprach-präfigierter Root pflegen (alternativ hreflang-bewusste Sektionen), inLanguage-Properties durchgehend im JSON-LD verdrahten und sicherstellen, dass jede übersetzte Seite die Heading-Anker-Struktur ihrer Quelle exakt spiegelt. Modelle, die vorwiegend auf englischen Inhalten trainiert wurden, routen nicht-englische Anfragen häufig fehlerhaft — explizite Sprach-Signale auf Entity- und Chunk-Ebene minimieren diesen Verlust nachhaltig.

Glossary.Glossar.

Working definitions for the technical terms this playbook uses with precision.

Arbeitsdefinitionen jener Fachbegriffe, die dieser Praxisleitfaden mit konsistenter Präzision verwendet.

RAG — Retrieval-Augmented Generation

The technical pattern in which an LLM first retrieves relevant source passages from an external corpus (the web, a knowledge base) and then generates its answer conditioned on those passages. The retrieval step is where website architecture decides whether your brand participates in the answer.

Das technische Muster, bei dem ein LLM zunächst relevante Quellenpassagen aus einem externen Korpus (Web, Knowledge Base) abruft und seine Antwort anschliessend konditioniert auf diese Passagen generiert. Im Retrieval-Schritt entscheidet die Website-Architektur darüber, ob eine Marke an der Antwort teilnimmt.

Tokenization

The process of cutting raw text into sub-word units (tokens) that an LLM can compute on. Token count is the operational unit of context-window budgets — every wrapper, banner or marketing flourish consumes tokens that cannot be spent on substance.

Der Prozess, rohen Text in Sub-Word-Einheiten (Tokens) zu segmentieren, auf denen ein LLM rechnen kann. Die Token-Anzahl bildet die operative Bezugseinheit jedes Kontextfenster-Budgets — jeder Wrapper, jedes Banner, jede Marketing-Geste beansprucht Token-Volumen, das für substanzielle Aussagen nicht mehr zur Verfügung steht.

Embedding vectorEmbedding-Vektor

A high-dimensional numerical representation of a text chunk produced by an embedding model. Vectors close together in this space represent semantically similar text. Retrieval ranks results by cosine similarity between the query vector and candidate chunk vectors.

Eine hochdimensionale numerische Repräsentation eines Text-Chunks, erzeugt durch ein Embedding-Modell. Im Vektorraum benachbarte Vektoren stehen für semantisch ähnlichen Text. Retrieval-Systeme gewichten Ergebnisse über die Cosine-Similarity zwischen Query-Vektor und Kandidaten-Chunk-Vektoren.

Semantic webSemantisches Web

The vision — partially realised — of a web in which machine-readable structured data lets software systems interpret content, not just display it. Schema.org and the linked-data movement (Wikidata, Google Knowledge Graph) are the most practically deployed pieces of this stack.

Die — teilweise realisierte — Vision eines Webs, in dem maschinenlesbare strukturierte Daten Softwaresystemen die Interpretation von Inhalten erlauben und nicht lediglich deren Anzeige. Schema.org sowie die Linked-Data-Bewegung (Wikidata, Google Knowledge Graph) repräsentieren die in der Praxis am breitesten implementierten Bausteine dieses Stacks.

User-Agent

The identifier string a client sends with every HTTP request, declaring what kind of software is calling. AI agents publish documented user-agent names — GPTBot, ClaudeBot, PerplexityBot — that robots.txt and edge routing rules can target.

Der Identifier-String, den ein Client mit jedem HTTP-Request mitsendet und über den die anfragende Software-Klasse deklariert wird. AI-Agenten publizieren dokumentierte User-Agent-Namen — GPTBot, ClaudeBot, PerplexityBot —, auf die sowohl die robots.txt als auch Edge-Routing-Regeln gezielt zugreifen können.

Entity ambiguityEntity-Mehrdeutigkeit

The condition in which an LLM cannot determine which real-world entity a name refers to — a shared company name, a product with a generic descriptor. Resolved by wiring JSON-LD sameAs references to authoritative external identifiers such as Wikidata Q-IDs.

Der Zustand, in dem ein LLM nicht eindeutig bestimmen kann, auf welche reale Entität sich ein Name bezieht — etwa bei geteilten Firmennamen oder Produkten mit generischer Bezeichnung. Aufgelöst durch JSON-LD-sameAs-Referenzen auf autoritative externe Identifier wie Wikidata-Q-IDs.

Agentic frameworkAgentisches Framework

A software system in which autonomous agents — typically LLM-backed — execute multi-step tasks against a target (a website, an API, a knowledge base) and produce a structured output. The BEE Guard Audit is an agentic framework: it scrapes, scores and generates remediation cards without a human in the loop.

Ein Softwaresystem, in dem autonome Agenten — typischerweise LLM-basiert — mehrstufige Aufgaben gegen ein Ziel (Website, API, Knowledge Base) ausführen und einen strukturierten Output produzieren. Das BEE Guard Audit ist ein agentisches Framework: Es scraped, scort und generiert Remediation-Cards vollständig ohne Human-in-the-Loop.

Deterministic scoreDeterministischer Score

A score computed from observable, repeatable measurements such that two runs on the same input produce the same output. The property is essential for longitudinal baselining — without it, the dashboard wobbles with model noise and ceases to be a credible reporting instrument.

Ein Score, der aus beobachtbaren, reproduzierbaren Messungen berechnet wird und bei identischem Input in jedem Lauf das identische Ergebnis liefert. Diese Eigenschaft ist Voraussetzung für jede longitudinale Baseline — ohne sie schwankt das Dashboard im Modell-Rauschen und verliert seine Glaubwürdigkeit als Reporting-Instrument.

llms.txt

A formalised root-level Markdown file (/llms.txt) that serves as a machine sitemap for LLM retrieval agents. Carries an H1 site title, a blockquote site abstract and explicit Documentation arrays referencing key pages and their Markdown variants. Larger estates pair it with /llms-full.txt for absolute Markdown payloads [3, 4].

Eine formalisierte Root-Level-Markdown-Datei (/llms.txt), die als Maschinen-Sitemap für LLM-Retrieval-Agenten fungiert. Sie transportiert einen H1-Site-Titel, ein Blockquote-Site-Abstract sowie explizite Documentation-Arrays mit Verweisen auf Schlüsselseiten und deren Markdown-Varianten. Umfangreichere Estates ergänzen sie durch /llms-full.txt für absolute Markdown-Payloads [3, 4].
